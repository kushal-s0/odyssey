## Configuration, migrations and operations

- New optional API names: `TEXT_DOCUMENT_SPACE_URL`, `SPEECH_TRANSLATION_SPACE_URL`, `HF_TOKEN`; only owned HTTPS hf.space origins, selected explicitly by backend.
- API needs separate `WORKER_CREDENTIAL` and `STAGE_CAPABILITY_SIGNING_KEY` (at least 32 chars). The model child receives neither; no DB/service credential is forwarded.
- Worker-only `.env.worker.local`: `WORKER_API_URL`, `WORKER_ID`, `WORKER_CREDENTIAL`, optional `HF_TOKEN`. Root/frontend missing placeholder files were prepared without overwriting existing values. Existing `.env` was untouched and remains ignored; it is not automatically loaded.
- New tables have RLS and no browser grants. One execution per stage/generation excludes duplicate inference entry. Publication stays atomic/idempotent. Explicit resume resets failed/cancelled/blocked attempts and fences cancelled work while retaining completed outputs/checkpoints.
- Source access uses fresh capability-protected API paths rather than public object URLs. API and worker verify SHA-256. Expired leases cannot be renewed; they must be reclaimed with a new generation. Late queued Gradio events fail closed before inference.
- Shared concurrency initially one across API replicas; no paid broker/worker. Runtime presence expires after 90 seconds. Sessions/backoff are bounded; no artificial anti-sleep traffic.
- This machine lacked the saved venv/DB/Docker/model cache. Recreated API/frontend dependencies and an ignored portable PostgreSQL instance on loopback 55432. Original archives and pre-existing `.tools` deletions were preserved. See `docs/SOURCES.md` for native tool licenses/build adaptations.
- Native pgvector initially failed to link `pg_strtof`; a local MinGW C99 compatibility shim fixed linking. First loaded build failed pseudo-relocation; `-mcmodel=large` fixed it before migrations and tests. This is local test infrastructure, not a release binary.
