# Judge graphs, explanations and synthetic samples

`ComparisonGraphs.tsx` uses the existing authorized analytics response. Grouped bars separate potential or dimension means from information completeness and evidence coverage; scatter points compare group means without claiming causation. All axes stay on 0-100, missing scores are omitted and Unknown is explicit in the table/CSV. Across-cohort values are split by trade. Small-sample flags now use the actual scored denominator. CSV quotes cells and neutralizes spreadsheet formulas in cohort names.

`AssessmentInsights.tsx` provides bars/radar of saved six-domain ratings. Null dimensions have no radar point and prevent the filled shape. Its confidence panel counts grounded fields, ambiguous/unreadable facts and source-review flags; none is a calibrated model probability or proof of external truth. Rating reasons and original evidence remain available beside the graph.

`ExplanationPanel.tsx` preserves the optional, explicit Groq request. Saved assessment identity is checked on every response; a request sequence prevents a slower GET replacing a newer generation, and assessment changes reset component state. Next actions link to known/missing business fields. Groq cannot change ratings. API schema/citations/numbers/cache/quotas remain guarded. English and Hindi live synthetic checks passed; no human language-quality certification follows.

`input/README.md` describes 18 openly synthetic text/PDF/audio examples, reference transcripts and expected facts. The keys distinguish applicant claims, derived arithmetic, conflicts, unknowns and pending review. Scans are rasterized typed pages; speech uses local Windows SAPI, not a real entrepreneur. Hashes and real local upload checks establish file integrity/admission, not model accuracy.

New submissions may explicitly set synthetic=true and a bounded scenario_family. Only synthetic records accept that field, and API adds an owner namespace to prevent collisions with real data/another applicant. The database's existing synthetic/family_id columns drive analytics exclusions. This requires no migration. Ordinary submissions retain defaults. No fake examples are inserted into Supabase by implementation or verification.

Committee answer: explainable means a reviewer can inspect the supplied source, unresolved fields, assumptions and versioned calculation. It does not mean that an LLM explanation proves accuracy, that a high score predicts success, or that synthetic samples validate a population.

An actual positive-sample run exposed extraction omissions and misattribution, rather than a graph defect: a multi-amount funding sentence was rejected as ambiguous, selling price was dropped and competitors/difference were interpreted as offer alternatives. `pipeline/explicit.py` now extracts bounded exact spans only from explicit English field labels and common money/unit phrases. It separates amounts by their stated roles, retains multiple prices, avoids unknown/range/abbreviation/instruction text and never computes a value. Model and typed-answer handling remain for other wording/languages. The policy is pinned as quoted-facts-v7-explicit-spans-and-unknown-context; existing outputs retain their original manifest. Generic intent to start a business is not an offer; a short quote cannot strip explicit uncertainty from its source statement. This conservative guard may require clarification when a sentence mixes known and unknown details. Text still requires appropriate source review. These patterns are not a general language-understanding accuracy claim.
