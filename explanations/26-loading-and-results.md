# Loading, navigation and inference time

Browser focus previously looked like a refresh because the Auth handler cleared its trusted actor on every Supabase SIGNED_IN notification. The installed SDK recovers its session when visibility returns and can emit this event again. Identical user/token notifications now reuse the session. A real token change still validates `/v1/me` in the background while preserving the existing workspace. Sign-out, account or access-scope changes discard private views; failed authorization clears the affected result. API authentication and database RLS remain authoritative.

App navigation previously replaced its rendered page. `KeptPanel` now mounts a work area on its first visit and preserves its state in memory. The applicant workspace retains at most three recently opened idea details; inactive details stop status polling. Other workspaces, draft answers, graph selections and scratchpad inputs survive internal navigation. This is memory only: hard refresh still discards unsent drafts. Scope keys include the actor's identity, role and cohort access. Each retained idea has distinct evidence anchors and heading IDs.

Retaining a page does not retain active microphone capture when its recording area is left. Both initial and follow-up recorders stop their tracks, finish the captured partial file and keep playback available on return. A pending permission response arriving while the panel is inactive releases its tracks. Deletion clears the retained current submission, assessment and job state. A browser test uses an explicit synthetic AudioContext stream with actual MediaRecorder chunks to verify stop/playback/draft behavior; no real microphone is used by the harness.

Completed results previously waited for three HTTP requests in sequence and automatically mounted every market/question/history tool. `/v1/submissions/{id}/workspace` now uses one SQL statement under the verified subject and authenticated role to return the current submission revision and its saved assessment. The read does not reconcile queues, dispatch work or invoke models. It never substitutes an older revision's result for the current one. Market, financial, question and history tools load only when visited; visited panels retain their data. Returning to an already opened result displays it while its authoritative snapshot is rechecked. A new revision or denied access clears the cached current view.

New assessments still run on the owned laptop. Model child startup, weight loading, extraction, optional OCR/ASR/translation, grounded structuring, domain judgments, embeddings and durable checkpoints all take time. The actual existing three-case synthetic text report measured86.86–140.219 seconds, not an instant response or a universal latency guarantee. Queue wait is additional. Opening a stored assessment does not repeat inference. No paid API, smaller unverified model, skipped evidence check or changed rubric was introduced for this repair.

Local browser verification exercises the SDK's real visibility callback and refreshed signed fixture token, preserves drafts across navigation, and deliberately withholds a reopened result's snapshot response to verify that its previous saved view remains visible. The fixture API uses actual local PostgreSQL/RLS; Auth/model/vector outputs are labelled fixtures. Separate current-revision/access tests verify the new snapshot endpoint. See T08/T05 reports and `evals/reports/product-ui.json` for the verification boundary.

The owned launcher also selects a five-second maximum idle polling interval for a healthy loopback API. The worker previously backed off to thirty seconds even when a new idea might arrive locally. Remote and error backoff stay at thirty seconds; no public free service is polled faster by this setting. CLI loop tests cover these differences. This changes work discovery delay; no fresh end-to-end GPU speedup is claimed.

One real configured Supabase test-account read compared the former three-request sequence (19.683 seconds) with the snapshot request (4.519 seconds) and verified identical assessment/revision payloads. The temporary diagnostic session sent no email, changed no password and was revoked afterward. No source content, account identifier or credential is stored in the timing report. This single observation is not a p95 or universal cloud latency guarantee; network/database time still applies to a first open. Previously visited results can render before background revalidation completes.
