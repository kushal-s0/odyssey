# Private uploads and durable submission intent

`routes/uploads.py` implements a three-step workflow: authenticated `POST /v1/uploads` records bounded intent; `PUT /v1/uploads/{id}/complete` streams original bytes to a private temporary file and validates them; `POST /v1/submissions` attaches the verified original to its immutable revision and durable job. Text skips the upload steps. No model runs inside these requests. A 202 means accepted for processing, not an assessment result.

Initiation requires a 16–128-character `Idempotency-Key`, a safe display filename, an allowed MIME type and a byte count up to 25 MiB. The object key is generated from trusted owner/attachment UUIDs, never from the supplied filename. A user can have at most five unattached pending uploads. Completion enforces the declared size/type, a sixty-second transfer bound and a SHA-256 content hash. Identical retries reuse the same original; different contents cannot overwrite it.

`services/inspect_media.py` runs in a separate Python process without service credentials. It checks actual signatures, rejects encrypted/truncated/over-limit PDFs and accepts up to twenty pages, including the required eleven-page scans. It fully decodes the single audio stream in OGG, MP4, browser WebM, WAV or MP3, rejects unsupported parameters/empty or over-ten-minute audio, and bounds packet timestamps as well as decoded duration. It never runs source instructions, PDF actions, links or model prompts. The parser has a twenty-second wall timeout, one parser slot per API process, and on Linux a fifteen-second CPU/384 MiB address-space limit. Windows currently has the wall timeout and concurrency bound; equivalent hard per-child memory enforcement is not yet verified. General HTTP/rate-limit hardening remains T21/T22.

`services/storage.py` streams validated bytes to private Supabase Storage with overwrite disabled. It supports recovery when an identical object was stored before a metadata transaction failed. Cloud operations remain unverified until the project is configured. An explicit `STORAGE_BACKEND=local` development/test adapter stores real files on disk; production rejects this setting. This adapter never silently replaces unavailable Supabase storage. Temporary API files are removed after each request and are not durable source storage.

Original downloads require a fresh resource check and bearer token, recheck the stored content hash and use no-store/download/sandbox headers. An assessor can read an assigned submission's original but cannot complete or cancel its owner's upload. `DELETE /v1/uploads/{id}` cancels only an owner's unattached original. It cannot delete attached evidence.

`routes/submissions.py` validates cohort membership and attachment ownership/readiness. A transaction creates the submission, revision, attachment binding, job, first extraction stage and idempotency response together. If any insert fails they roll back together. Source text is preserved exactly. Global admission and per-user active-job counts are serialized in PostgreSQL, so separate API processes cannot admit the same capacity concurrently. This task creates job intent only; T07 implements execution, progress and recovery, then T09/T10/T11 implement actual extraction.

`repositories/idempotency.py` scopes keys to owner and operation, compares a canonical request hash and serializes simultaneous duplicates with transaction advisory locks. Reusing a key for changed input returns 409. Another user's identical key cannot reveal or return the first user's submission. Listing/detail reads use verified-subject RLS, bounded pagination and immutable current revisions.

Unattached uploads expire after twenty-four hours. The trusted operator can run `.venv/Scripts/python.exe -B scripts/cleanup_uploads.py --execute` against the intended configured project. Each batch locks at most fifty eligible rows, deletes private objects first and then retires metadata. Failures leave metadata retryable; attached originals are excluded. Run this manually during the demo and later on an approved scheduled platform; no hosted scheduler is claimed deployed.

## Actual evidence

`evals/reports/uploads-corpus.json` records all 55 private organizer files passing the actual local routes with real PostgreSQL and the explicit disk adapter: 42 PDFs/109 pages, eleven MP4 and two OGG recordings, four eleven-page scans. Authorized downloads matched every original byte and archive hashes were unchanged. No private names, text, recordings or file bytes are in the public report. Synthetic WebM/WAV/MP3, spoofed/encrypted/truncated/oversized inputs, ownership, retries, concurrent duplication, cancellation, capacity and transaction rollback have separate API tests. These checks do not establish live Supabase Storage behavior or model extraction quality.
